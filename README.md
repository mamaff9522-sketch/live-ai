# Live AI

ผู้ช่วย AI ภาษาไทยที่ใช้ **Qwen3.5-2B (GGUF Q4_K_M)** เป็นสมองหลัก รันบน **CPU ล้วน** ผ่าน llama.cpp
ไม่ใช้ API เสียเงิน และไม่ต้องใช้ GPU

## ทำอะไรได้
- สนทนาภาษาไทย ตอบคำถาม อธิบายความรู้ คิดวิเคราะห์ (มีโหมด "คิดละเอียด")
- เขียนและตรวจโค้ด ช่วยวางแผนงาน
- จำบริบทในบทสนทนา และจำข้อมูลระยะยาวของผู้ใช้แต่ละคน
  - พิมพ์ `จำไว้ว่า ...` เพื่อให้จำ และ `ลืมเรื่อง ...` เพื่อให้ลืม
  - ดูหรือลบสิ่งที่จำได้จากเมนู ☰
- ผู้ใช้แต่ละคนมีรหัสเข้าใช้ของตัวเอง ประวัติและความจำแยกขาดจากกัน
  (ทุกคำสั่งในฐานข้อมูลกรองด้วยเจ้าของ เดาเลขบทสนทนาของคนอื่นก็เปิดไม่ได้)

## ระบบความทนทาน
| เรื่อง | ทำงานอย่างไร |
|---|---|
| โมเดลล่มหรือค้าง | ตัวเฝ้าระบบตรวจทุก 5 วินาที แล้วรีสตาร์ตเองแบบหน่วงเวลาเพิ่มขึ้น ข้อความที่ส่งระหว่างนั้นจะรอและส่งซ้ำให้อัตโนมัติ |
| คนใช้พร้อมกันหลายคน | ตอบทีละข้อความตามคิว เพราะ CPU มีจำกัด แต่ละคนส่งซ้อนกันไม่ได้ |
| บทสนทนายาวเกินหน่วยความจำของโมเดล | ตัดประวัติเก่าออกให้พอดีโดยอัตโนมัติ |
| Log | `data/logs/live_ai.log` เป็น JSON ทีละบรรทัด ไม่บันทึกข้อความแชตหรือรหัสผู้ใช้ และมี `llama_server.log` แยก |
| สำรองข้อมูล | สำรองฐานข้อมูลทุกครั้งที่เปิดระบบและทุกวัน เก็บ 14 ชุดล่าสุด |
| ย้อนกลับ | `python -m live_ai.backup list` แล้ว `python -m live_ai.backup restore <ไฟล์>` (ระบบจะสำรองของปัจจุบันก่อนเสมอ) ส่วนโค้ดย้อนกลับได้ด้วย git ทุกคอมมิต |

## การปรับให้เข้ากับเครื่อง
ค่าเริ่มต้นจะปรับตามเครื่องเอง: จำนวน thread เท่ากับจำนวน CPU และขนาด context ตาม RAM
(2 GB → 2048, 3.5 GB → 4096, 6 GB → 8192, 12 GB ขึ้นไป → 16384) ถ้าต้องการกำหนดเอง ใช้ตัวแปรเหล่านี้:

| ตัวแปร | ความหมาย |
|---|---|
| `LIVEAI_THREADS` | จำนวน thread ของ CPU |
| `LIVEAI_CTX` | ขนาด context (โทเคน) |
| `LIVEAI_QUANT` | ระดับ quantization เช่น `Q4_K_M` (ค่าเริ่มต้น) หรือ `Q3_K_M` ถ้า RAM น้อยมาก |
| `LIVEAI_MAX_REPLY_TOKENS` | ความยาวคำตอบสูงสุด |
| `LIVEAI_MODEL_PATH` / `LIVEAI_MODEL_URL` | ใช้ไฟล์โมเดลที่มีอยู่แล้ว หรือกำหนดลิงก์เอง |
| `LIVEAI_ADMIN_KEY` | รหัสผู้ดูแล ใช้สั่งสำรองข้อมูลผ่าน API |
| `LIVEAI_OPEN_REGISTRATION` | `0` = ปิดรับสมัครผู้ใช้ใหม่ |

## แหล่งโมเดล
ระบบหาไฟล์ Q4_K_M จากผู้เผยแพร่ที่เชื่อถือได้ตามลำดับ (ทีม Qwen ทางการก่อน แล้ว Unsloth ฯลฯ)
และตรวจ SHA-256 ของไฟล์ที่ดาวน์โหลดกับค่าที่ Hugging Face ประกาศ ถ้าไม่ตรงจะไม่ใช้งาน

## การทดสอบ
- `python -m unittest tests.test_offline -v`: ทดสอบทั้งระบบด้วยโมเดลจำลอง (แยกผู้ใช้, ความจำ, กู้คืน, log, สำรองข้อมูล)
- GitHub Actions (`.github/workflows/test.yml`) ดาวน์โหลด Qwen3.5-2B ของจริง รันบน CPU 2 คอร์ แล้วทดสอบภาษาไทย ความรู้ คณิต
  การเขียนโค้ด (รันโค้ดที่โมเดลเขียนจริง) การวางแผน ความจำ การแยกผู้ใช้ การใช้งานต่อเนื่อง 10 รอบ และการกู้คืนหลังฆ่าโปรเซสโมเดล
  ผลอยู่ในหน้า Actions → รายงาน `real-model-report`
- ทดสอบ Docker image ว่าเปิดขึ้นและตอบภาษาไทยได้

## รัน
```bash
# ต้องมี llama-server ของ llama.cpp
LIVEAI_LLAMA_SERVER=/path/to/llama-server python -m live_ai     # เปิด http://localhost:7860
# หรือ
docker build -t live-ai . && docker run -p 7860:7860 -v live-ai-data:/data live-ai
```
